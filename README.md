# 模型指纹技术研究进展

> 更新日期：2026-07-20
> 目标：持续整理模型指纹（model fingerprinting）及其相邻技术在模型知识产权保护、模型来源识别、训练数据追踪和生成式 AI 内容溯源中的研究进展。

## 1. 概念与问题边界

模型指纹技术用于识别一个可疑模型是否来自某个目标模型、目标训练流程或目标数据集合。它通常服务于三类场景：

1. **模型所有权验证**：判断被盗用、蒸馏、微调或重新部署的模型是否源自权利人模型。
2. **模型来源识别**：在只可访问 API 的黑盒条件下，识别应用背后使用的模型家族、版本或供应商。
3. **训练数据追踪**：判断特定数据或数据集是否被用于训练某个模型。

需要区分几个相近概念：

| 技术 | 是否改动训练/模型 | 主要证据 | 常见访问条件 | 典型用途 |
| --- | --- | --- | --- | --- |
| 模型指纹 | 通常非侵入，也可包含轻量嵌入 | 查询响应、表示空间、权重统计、决策边界 | 黑盒或白盒 | 被盗模型识别、版本识别 |
| 模型水印 | 通常侵入训练或后处理 | 触发集响应、权重水印、输出分布 | 黑盒或白盒 | 所有权声明、版权证明 |
| 数据水印/放射性数据 | 改动训练数据 | 被训练模型对标记数据的统计响应 | 多为白盒或灰盒 | 数据使用证明 |
| 内容水印/来源凭证 | 改动生成过程或元数据 | 图像/文本/音频中的隐藏信号或签名元数据 | 输出内容可见 | AIGC 内容溯源 |

在工程和法务语境中，指纹证据通常不能单独证明侵权，需要与模型访问日志、训练数据授权记录、部署链路、统计显著性和可重复实验共同构成证据链。

## 2. 技术谱系

### 2.1 DNN 模型指纹：从分类边界到行为签名

早期深度模型 IP 保护主要围绕图像分类器和传统 DNN 展开，核心问题是如何在不获取权重的情况下，通过少量查询验证模型身份。

常见思路包括：

- **决策边界指纹**：寻找靠近目标模型决策边界、对模型差异敏感的样本。若可疑模型来自目标模型，其响应模式会在这些样本上保持相似。
- **对抗样本/触发样本指纹**：使用目标模型特有的脆弱点构造查询集合，观察可疑模型是否复现相同标签或置信度。
- **稳定区域与边界区域结合**：同时覆盖高置信样本和边界样本，以兼顾稳定性与区分度。
- **表示空间/中间特征指纹**：在白盒或灰盒条件下比较激活、logits、权重统计或 embedding 分布。

研究趋势从“单个触发集是否命中”转向更系统的统计检测：查询如何选择、特征如何表示、相似性如何检验、误报率如何校准。2024 年以后，相关综述开始用统一框架描述模型 IP 保护，把模型水印、模型指纹、访问控制和攻击面放在同一分类体系下。

### 2.2 模型水印：更强声明能力与更高侵入性

模型水印把秘密信息嵌入模型，常见方式包括：

- **权重水印**：在参数或特定层中嵌入可提取信号。
- **后门触发水印**：训练模型对一组秘密触发样本输出指定标签或文本。
- **动态水印**：在线服务中对特定查询返回带标记的响应，使被抽取模型继承水印行为。
- **输出分布水印**：轻微改变 token 或类别输出分布，使统计检测器可识别。

优势是证据更直接，劣势是可能影响模型质量、引入安全风险，并可能被微调、剪枝、量化、蒸馏、模型合并或水印移除攻击削弱。当前研究更强调“水印是否无害、是否隐蔽、能否抗后训练、是否可扩展到大量授权用户”。

### 2.3 训练数据指纹与数据集推断

当资产的核心是数据集而不是模型权重时，研究重点转为“模型是否训练过某些数据”。

- **Radioactive Data（放射性数据）**：对少量训练样本加入人眼不可见扰动，使任何用这些样本训练出的模型带有统计可检出的痕迹。原论文在 ImageNet 等任务上展示：即使只标记约 1% 训练数据，也可用显著性检验检测使用痕迹。
- **Dataset Inference（数据集推断）**：不显式修改数据，而是利用被抽取模型会继承目标训练集知识这一现象，通过特定样本集和统计检验判断模型是否源自目标数据或目标模型。
- **数据水印鲁棒性研究**：后续工作指出，数据水印在强对抗设定下仍面临数据清洗、增强、再训练和模型抽取攻击，需要结合访问日志和多轮验证。

这一方向适合数据集授权、训练集泄露追踪和模型供应链审计，但对数据分布、模型架构和训练流程变化较敏感。

### 2.4 LLM 指纹：从文本水印到模型版本识别

大语言模型带来新的指纹问题：模型规模大、输出随机、API 不暴露 logits、应用层可能叠加系统提示、RAG、工具调用或安全过滤。研究路线大致分为四类：

1. **主动查询式指纹**
   设计少量高区分度 prompt，通过输出风格、事实偏好、拒答模式、格式习惯或特定能力边界识别模型版本。LLMmap 等工作表明，在复杂应用层下仍可通过精心查询识别背后 LLM 版本。

2. **嵌入式 LLM 指纹**
   在模型分发前植入授权用户特定的 prompt-response 映射或 token 偏好。2025 年的 Scalable Fingerprinting of LLMs 提出 Perinucleus sampling，强调可扩展性：同一 8B 模型可植入上万级指纹，同时保持效用并在监督微调后保留指纹。

3. **内在表示指纹**
   不额外训练或嵌入信号，而是利用模型内部表示、logits 空间、语义偏好或生成统计作为天然指纹。REEF 等工作探索训练无关的表示指纹，以降低对模型效用的影响。

4. **文本水印作为模型指纹证据**
   绿色列表/红色列表 token 偏置、语义水印、句法或风格约束可用于识别某类模型输出，但在改写、翻译、摘要、多模型混合和采样参数变化下鲁棒性仍是难点。

LLM 指纹的核心挑战是：低查询成本、低误报率、对系统提示/RAG/温度变化鲁棒、对模型合并和微调持久，同时不泄露指纹密钥、不影响用户体验。

### 2.5 扩散模型与生成内容水印

扩散模型领域的“指纹”更多落在生成内容溯源上，和模型所有权验证相邻但不完全相同。

- **Stable Signature**：通过微调生成模型，使生成图像携带可检测签名。
- **Tree-Ring Watermark**：在初始噪声频域中嵌入结构化模式，生成图像后仍可检测。
- **Gaussian Shading / PRC 类语义水印**：通过采样初始 latent noise 的方式嵌入分布保持水印，研究重点逐渐转向密码学假设、密钥管理和多次生成场景。
- **SynthID 与 C2PA**：产业界同时推进不可感知水印和加密元数据凭证。SynthID 偏向内容中嵌入检测信号，C2PA 偏向记录内容捕获、编辑和生成的来源链。

近期攻击研究显示，语义水印可能被代理模型伪造或移除；因此内容水印不应被视为单点安全机制，而应与平台侧日志、模型端签名、内容凭证和风险检测组合使用。

## 4. 评测指标

模型指纹方案至少应报告以下指标：

- **有效性（effectiveness）**：对同源模型的检出率、召回率、统计显著性。
- **可靠性（reliability）**：对非同源模型的误报率、置信区间、阈值选择依据。
- **无害性（harmlessness）**：对主任务准确率、困惑度、对齐质量、安全策略和用户体验的影响。
- **隐蔽性（stealthiness）**：攻击者是否能通过异常 query、异常样本、异常 token 分布或权重统计发现指纹。
- **鲁棒性（robustness）**：对微调、剪枝、量化、蒸馏、模型抽取、模型合并、提示改写、输出改写、数据增强的保持能力。
- **可扩展性（scalability）**：支持多少授权用户或模型副本，指纹之间是否互相干扰，密钥管理成本如何。
- **可审计性（auditability）**：验证过程是否可复现，是否能给出 p-value、置信区间、查询记录和不可抵赖证据。
- **查询成本（query efficiency）**：黑盒验证所需 query 数、API 成本、被限流或检测的风险。

## 5. 攻击面与防御思路

| 攻击/风险 | 影响 | 防御思路 |
| --- | --- | --- |
| 微调与继续训练 | 淡化触发行为或输出偏置 | 使用多区域指纹、持久表示指纹、训练后鲁棒性评测 |
| 剪枝、量化、蒸馏 | 改变权重和边界细节 | 关注功能等价和统计响应，而非单点权重模式 |
| 模型抽取 | 新模型继承部分行为但不继承水印 | 结合动态水印、数据集推断、访问日志和查询追踪 |
| 模型合并 | 混合多个模型来源，稀释单一指纹 | 设计可组合检测指标，研究指纹转移/移除边界 |
| 查询过滤 | 服务方识别并拒绝指纹 query | 提升 query 自然度，使用语义多样、任务相关的验证集 |
| 输出改写 | 改写文本或图像后破坏水印 | 使用语义级、多模态、多尺度检测，保留原始响应证据 |
| 伪造指纹 | 攻击者制造“看似同源”的证据 | 引入密钥、nonce、时间戳、签名日志和第三方见证 |

## 6. 落地建议

1. **先定义威胁模型**：明确要防的是模型泄露、API 抽取、数据盗用、版本冒用还是生成内容伪造。
2. **组合证据优于单点检测**：模型指纹、水印、访问控制、日志审计、内容凭证和合同记录应共同使用。
3. **为每个模型副本分配独立指纹**：商业分发场景中需要可追踪到用户或部署节点，避免所有副本共享同一指纹。
4. **保留验证协议**：记录指纹生成种子、密钥版本、查询集 hash、时间戳、API 响应和统计检验脚本。
5. **持续做红队评估**：验证方案必须经过微调、蒸馏、量化、合并、RAG 封装、提示改写和内容再编码测试。
6. **谨慎处理法务结论**：技术检测结果应表达为概率和置信度，不宜直接写成绝对归因。

## 7. 后续研究方向

- **LLM 应用层指纹**：在系统提示、RAG、工具调用、代理框架和多模型路由存在时，如何稳定识别底层模型。
- **多模态统一指纹**：统一文本、图像、音频、视频模型的指纹生成、验证和证据表达。
- **抗模型合并与持续微调**：研究指纹在 LoRA 合并、模型融合、领域继续训练后的可保留边界。
- **低查询、高置信验证**：降低线上黑盒验证成本，同时控制误报率和被检测风险。
- **密码学与统计检测结合**：把密钥、nonce、签名日志和显著性检验纳入同一验证协议。
- **标准化基准**：建立覆盖模型水印、模型指纹、数据集推断和内容水印的统一 benchmark。
- **合规与可解释证据链**：面向司法、监管和企业审计，把技术指标转化为可解释、可复核的报告格式。
