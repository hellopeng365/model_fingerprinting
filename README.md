# 模型指纹技术研究进展

> 更新日期：2026-07-27
> 主题：模型指纹、模型水印、训练数据溯源与大模型版权审计

## 1. 研究问题

模型指纹（model fingerprinting）关注如何为机器学习模型建立可验证的“身份特征”，以支持模型版权保护、模型盗用检测、衍生模型溯源、训练数据使用审计和生成内容归因。随着开源模型复用、模型蒸馏、模型合并、量化部署和 API 化服务变得常见，传统软件版权保护方式难以直接适用于神经网络权重与模型行为，因此模型指纹逐渐成为 AI 安全与知识产权保护中的重要方向。

相关概念之间常有交叉，但研究目标和实施方式有所不同：

| 概念 | 是否主动嵌入 | 典型验证对象 | 主要用途 | 常见风险 |
| --- | --- | --- | --- | --- |
| 模型指纹 | 可主动，也可被动 | 权重、表示、输出行为、特定查询响应 | 所有权验证、模型族识别、衍生模型追踪 | 指纹稳定性、误报、查询成本 |
| 模型水印 | 通常主动嵌入 | 参数、触发集、生成分布、输出文本 | 版权声明、黑盒/白盒验证 | 被微调、剪枝、蒸馏、改写攻击移除 |
| 数据指纹/数据水印 | 主动标记训练样本或数据分布 | 训练后模型或生成结果 | 数据集使用审计、数据泄露追踪 | 数据质量影响、跨域泛化不足 |
| AIGC 内容水印 | 主动影响生成内容 | 文本、图像、音频、视频内容 | 生成内容识别与平台治理 |  paraphrase/编辑/压缩/重采样攻击 |

## 2. 威胁模型与验证设定

模型指纹方案通常需要同时说明访问权限、攻击者能力和判定标准。

### 2.1 访问权限

- **白盒验证**：验证方可访问模型参数、梯度或中间表示。优点是检测信号强；缺点是对闭源 API 与托管模型不适用。
- **黑盒验证**：验证方只能提交查询并观察 logits、概率、标签或自然语言输出。实用性更高，但更依赖查询设计、统计检验和误报控制。
- **灰盒验证**：可访问部分信息，例如 embedding、隐藏状态、少量校准样本、系统提示或受限日志。

### 2.2 攻击者能力

常见攻击包括微调、剪枝、量化、蒸馏、模型合并、权重平均、LoRA/adapter 注入、系统提示改写、RAG 外挂、输出后处理、文本改写和指纹反向工程。面向大模型的研究尤其需要考虑：

- **参数改变型后处理**：继续预训练、SFT、RLHF/DPO、量化、剪枝、模型合并。
- **参数无关型部署变化**：system prompt、RAG、工具调用、解码参数、拒答策略和安全对齐层。
- **自适应攻击**：攻击者知道指纹方案或可收集少量带水印输出后，主动优化以规避检测。

### 2.3 判定指标

一个可落地的指纹系统通常不只报告准确率，还需要给出统计置信度和误判代价：

- **TPR/FPR**：在固定低误报率下的真阳性率，版权场景应特别关注低 FPR。
- **ROC-AUC / IP-ROC**：衡量不同阈值下的所有权验证能力。
- **p-value / 置信区间**：用于支持“是否使用了某数据或模型”的统计结论。
- **鲁棒性**：经过微调、量化、剪枝、蒸馏、模型合并、改写等操作后仍可检测。
- **不可伪造性与唯一性**：不同模型、不同模型族、独立训练模型之间应低碰撞。
- **保真度**：嵌入指纹后不能显著损害原任务性能、文本质量或安全对齐效果。
- **查询成本**：黑盒验证需要控制触发样本数量、token 成本和 API 调用成本。

## 3. 技术路线

### 3.1 参数级水印与白盒指纹

早期神经网络水印多在参数空间中嵌入签名，例如在正则项中约束部分权重映射到比特串，或在模型内部表示中加入可检测模式。这类方法检测信号明确，适合自有模型发布后的白盒审计，但在模型经过大规模微调、重新训练、剪枝或结构迁移后可能退化。

代表工作：

- Uchida et al., 2017：将水印嵌入 DNN 权重，是深度模型水印的早期代表。
- DeepSigns, 2019：在激活概率分布中嵌入签名，兼顾白盒与部分黑盒场景。
- 后续研究扩展到 CNN、GNN、推荐模型和联邦学习模型，并尝试提升对剪枝与微调的稳定性。

### 3.2 触发集与黑盒所有权验证

黑盒模型水印通常构造一组秘密触发输入，使受保护模型在这些输入上输出预设标签或特定文本。验证时只需访问 API，因此更贴近商业部署。其核心挑战是触发样本要足够自然、难以猜测，并且不能引入明显后门风险。

典型方法包括：

- 使用边界样本、对抗样本或不可见样本作为触发集。
- 让触发集保持语义合理，降低被过滤或人工发现的概率。
- 在分类、检测、生成式模型中分别设计标签触发、行为触发和输出模式触发。

主要不足：

- 触发集可能被微调、蒸馏或模型编辑削弱。
- 若触发样本分布异常，容易被输入过滤器识别。
- 在法律或审计场景中，需要证明触发行为不是自然碰撞或过拟合偶然现象。

### 3.3 行为指纹与被动模型识别

被动模型指纹不一定修改模型，而是从模型固有行为中提取特征，例如：

- 决策边界附近的响应模式。
- 特定查询集上的 logit 排序、置信度曲线或错误分布。
- 隐藏表示方向、拒答行为、安全策略、风格偏好。
- 多任务能力、知识边界和失败模式组合。

这类方法适合识别模型族、基础模型来源或疑似衍生模型，但要避免把任务数据偏差、提示词差异或部署层策略误判为模型身份。

2025 年 AAAI 的 QuRD（Query, Representation, Detection）框架将模型指纹拆分为查询、表示和检测三个模块，显示许多复杂指纹方案与简单基线相比优势并不总是明显，推动研究从“提出新方案”转向“标准化评测与强基线比较”。

### 3.4 训练数据指纹与数据使用审计

数据层面的指纹用于回答“某批数据是否被用于训练”。典型代表是 Radioactive Data：对图像样本加入视觉上难以察觉的标记，使训练后的模型在特征空间中留下可统计检测的痕迹。该方法可用 p-value 给出置信度，并在 ImageNet、ResNet/VGG/DenseNet 等设置中展示了对架构和数据增强的鲁棒性。

数据指纹适合数据交易、授权训练、数据泄露追踪等场景，但落地时需要关注：

- 标记是否影响数据质量与下游模型性能。
- 标记比例较低时的检测功效。
- 是否可在文本、多模态和合成数据场景中稳定传播。
- 与隐私保护、数据许可和合规审计流程如何结合。

### 3.5 大语言模型（LLM）指纹与版权审计

LLM 使模型指纹问题更复杂：模型可能经历 SFT、RLHF、DPO、量化、LoRA、模型合并、系统提示封装和 RAG 增强；输出又受到采样参数和安全策略影响。因此近年研究从单一触发集转向多层信号融合。

主要方向：

1. **生成式水印**：在 token 采样或 logits 中引入统计偏置，用于检测生成文本是否来自某模型或系统。优点是可用于内容治理；缺点是对改写、翻译、摘要、拼接和自适应攻击敏感。
2. **行为指纹**：通过一组提示测量模型风格、知识边界、拒答模式、推理错误和安全偏好。优点是不一定改动模型；缺点是容易受系统提示、RAG 和后处理影响。
3. **白盒表示指纹**：利用隐藏状态、表示方向或参数统计识别模型族。优点是信号强；缺点是需要访问权重或内部表示。
4. **鲁棒黑盒所有权验证**：通过优化触发提示、目标输出和统计阈值，使指纹在微调、量化、合并后仍能保留。

近期值得关注的进展：

- **MERGEPRINT（ACL 2025）**：面向模型合并风险，优化可在合并后保留的黑盒指纹。
- **LeaFBench / LLM fingerprinting SoK（2025）**：提出面向 LLM 指纹的系统化分类和基准，覆盖多种基础模型与后开发技术。
- **DuFFin（EACL 2026 Findings）**：结合触发模式与知识层级指纹，用于 LLM 黑盒所有权验证，并在微调、量化、安全对齐变体上报告较高 IP-ROC。
- **拒答向量行为指纹（2026）**：利用安全对齐形成的拒答表示方向进行模型族溯源，强调微调、合并和量化后的可追踪性。

## 5. 当前研究趋势

### 5.1 从单点信号走向多证据链

单一触发集或单一统计特征难以覆盖复杂部署环境。更可靠的方向是将多个证据组合起来：触发响应、自然查询行为、表示方向、输出风格、知识边界、训练数据痕迹和部署日志。多证据链可降低误报，也更符合审计或法律举证需求。

### 5.2 从“能检测”走向“可比较、可复现、可审计”

研究社区逐渐重视标准化基准、强基线、统一指标和开放工具箱。未来方案需要报告数据集、模型族、后处理攻击、查询预算、阈值选择和统计置信度，而不是只展示单一准确率。

### 5.3 大模型场景强调衍生链路追踪

LLM 的衍生链路可能包含继续训练、指令微调、偏好对齐、模型合并、adapter 叠加和服务端包装。指纹技术需要回答更细的问题：是同一模型、同一模型族、同一训练数据来源，还是仅仅共享公开基座？

### 5.4 与内容水印、数据治理和合规审计融合

模型指纹不应孤立使用。实际系统中可能同时需要：

- 模型发布前的参数/行为指纹登记。
- 授权数据集的可追踪标记。
- 生成内容水印与平台检测。
- API 查询日志、版本发布记录和供应链元数据。
- 可复验的第三方审计流程。

## 6. 主要挑战

1. **误报责任高**：版权指控必须在极低 FPR 下仍保持可解释证据。
2. **自适应攻击增强**：攻击者可通过蒸馏、改写、模型合并和 RL 优化主动规避检测。
3. **模型行为非稳定**：LLM 输出受解码、系统提示、RAG、安全策略和上下文影响。
4. **开放基座混淆**：许多模型共享同一 foundation model，区分“合法微调”与“非法复制”更难。
5. **跨模态扩展不足**：图像、音频、视频、多模态模型的指纹传播机制和攻击面不同。
6. **法律可采性不足**：技术指标需要转化为可解释、可复验、可审计的证据链。

## 7. 建议的研究路线

面向后续研究或工程落地，可优先推进以下方向：

- **建立统一评测集**：覆盖分类模型、视觉模型、LLM、多模态模型以及常见后处理操作。
- **低误报统计检验**：在固定 0.1% 或更低 FPR 下报告 TPR，并给出置信区间。
- **黑盒查询优化**：减少验证查询数量，同时避免触发样本过于异常。
- **模型合并与蒸馏鲁棒性**：将 merge、distillation、quantization 作为默认攻击而非附加实验。
- **多层指纹融合**：结合参数、表示、行为、数据和内容水印，形成可解释证据链。
- **隐私保护验证**：探索零知识证明、哈希承诺、可信执行环境等方式，减少泄露私有指纹或模型细节。
- **面向治理的工具化**：提供登记、检测、报告生成和审计复验流程。

## 9. 结论

模型指纹技术正在从传统 DNN 参数水印和触发集验证，扩展为覆盖数据、模型、行为和生成内容的综合溯源体系。短期内，黑盒验证、低误报统计、模型合并鲁棒性和 LLM 衍生模型追踪会是重点；长期看，模型指纹需要与数据治理、内容水印、供应链元数据和第三方审计结合，才能真正支撑可执行的 AI 知识产权保护。
