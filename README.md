# 模型指纹技术研究进展

> 更新时间：2026-07-13
> 主题：模型指纹（model fingerprinting）、模型水印（model watermarking）、数据集归属验证、LLM 身份标识与 AIGC 水印的研究脉络。

## 1. 背景与问题定义

深度学习模型和大语言模型的训练通常依赖高成本的数据、算力、调参经验和工程管线。模型发布后，攻击者可能通过复制权重、微调、剪枝、量化、蒸馏、API 抽取、迁移学习或模型合并等方式复用模型能力，从而产生知识产权归属和授权合规问题。模型指纹技术的目标是在不依赖人工审计完整训练流程的情况下，为“某个可疑模型是否源自受保护模型或数据”提供可量化证据。

常见概念边界如下：

| 概念 | 核心对象 | 是否侵入训练/模型 | 典型验证方式 | 代表用途 |
| --- | --- | --- | --- | --- |
| 模型指纹 | 已训练模型的行为、决策边界、表征或梯度场 | 通常非侵入，也可主动植入 | 黑盒 API 查询或白盒特征比较 | 模型盗用检测、模型复用检测 |
| 模型水印 | 权重、激活、后门触发器或输出分布中的秘密标识 | 多数需要训练时或微调时嵌入 | 触发集、权重提取、统计检验 | 所有权声明、授权追踪 |
| 数据集指纹/数据水印 | 训练数据中的可追踪信号 | 对数据做标记或利用私有数据差异 | 判断模型是否吸收特定数据知识 | 数据资产保护、训练数据使用证明 |
| AIGC/内容水印 | 生成文本、图像、音频或视频 | 通常作用于生成过程或输出内容 | 对内容做统计检测或解码 | 生成内容溯源、平台治理 |

模型指纹和模型水印经常被混用。本文采用较窄定义：**模型指纹强调从模型固有或可验证行为中提取唯一性证据；模型水印强调主动向模型或输出中嵌入秘密标识**。在 LLM 场景中，二者边界正在变得模糊，例如“语义条件水印”可作为模型指纹使用。

## 2. 通用流程

一个完整的模型指纹方案通常包含四个阶段：

1. **威胁建模**：明确可疑模型的访问方式（黑盒/灰盒/白盒）、攻击类型（微调、蒸馏、量化、合并等）和判定目标（同源、复用、盗版、训练数据使用）。
2. **指纹生成**：选择查询样本、决策边界点、对抗样本、自然样本、私有样本或语义域提示，并保存模型在这些输入上的特征。
3. **指纹表示**：将输出标签、置信度、logits、激活、梯度、解释结果或生成文本统计量编码成可比较的表示。
4. **归属判定**：通过阈值、假设检验、相似度度量、分类器或多指标投票给出判定，并报告误报率、漏报率和置信度。

近年的系统化工作把上述流程拆成更可组合的模块。例如 QuRD 将分类器模型指纹拆分为 **Query Sampling、Representation、Detection** 三部分，用于公平复现、组合和基准化不同方案。

## 3. 传统 DNN/分类器模型指纹

### 3.1 从决策边界和对抗样本开始

早期 DNN 指纹多围绕分类器的决策边界展开。核心假设是：即使两个模型在普通测试集上准确率接近，它们在边界附近、对抗扰动或置信度空间中的行为仍具有模型特异性。

- **IPGuard**：在模型分类边界附近提取样本，用这些样本及其预测结果作为模型指纹。优势是无需改动原模型，理论上不牺牲模型精度；局限是依赖同标签空间和边界查询质量。
- **Conferrable adversarial examples / FCAE**：构造能迁移到被盗模型、但不迁移到独立参考模型的对抗样本，增强“同源模型”与“无关模型”的区分。
- **ModelDiff**：从“输入对”的响应距离构造 Decision Distance Vector（DDV），用余弦相似度比较模型行为，可用于迁移学习、压缩、模型抽取等复用场景。

这类方案推动了黑盒模型所有权验证，但也暴露出共同问题：单一查询集或单一指标容易被自适应攻击、输出过滤、重新训练或标签空间变化削弱。

### 3.2 测试框架与多证据链

随后研究开始把模型指纹问题看作软件测试和模型相似性比较问题。

- **DeepJudge**：将版权保护转化为多层级测试框架，生成测试用例并组合多种指标，对微调、剪枝、抽取等场景给出证据链，而不是依赖单一指纹。
- **NFARD / Reuse Zoo**：关注无对抗样本的复用检测和更系统的复用基准，强调生成测试集的效率、异构复用类型和真实模型复用链路。
- **ModelGiF**：使用梯度场刻画模型功能距离，为异构预训练模型提供更统一的表示，试图缓解只比较标签或 logits 的局限。

趋势上，DNN 指纹正在从“找到一个秘密触发集”转向“构建可复现、可校准、可解释的模型行为比较协议”。

### 3.3 基准化与可比性

2024-2025 年的一个重要进展是对评测方法本身的反思。QuRD 指出，许多指纹方案的实验假设、模型对生成方式、攻击强度和基准难度并不一致；一些简单基线在特定任务上能接近复杂方案。因此，后续研究需要：

- 明确训练集、参考模型、可疑模型和攻击者能力的生成方式；
- 同时报告 TPR、FPR、AUC、TPR@固定 FPR、查询预算和置信区间；
- 引入更难的负样本，例如同架构独立训练、同数据不同初始化、同基础模型不同微调、跨任务迁移；
- 将指纹生成、表示和检测模块拆开，避免把查询集效果、表示能力和判定阈值混在一起比较。

## 4. 数据集归属与训练数据级指纹

模型能力往往来自训练数据，因此数据集归属验证是模型指纹的重要补充。

- **Dataset Inference**：利用模型在私有训练样本和公共样本上的行为差异，通过统计检验判断可疑模型是否吸收了原始数据知识。该方法不要求修改训练流程，在黑盒场景下也可以通过 API 查询实现。
- **Radioactive Data**：主动对一小部分训练图像做视觉上不可感知的标记，使任何使用这些数据训练出的模型都带有可检测信号，并用 p-value 给出置信度。
- **数据/模型联合保护**：新近综述强调不仅要保护模型权重，也要保护数据集智能（dataset intelligence）。在实际纠纷中，训练数据来源、数据处理流水线和模型行为证据往往需要联合呈现。

数据集指纹的优势是和模型结构无关，能覆盖蒸馏或抽取后仍保留的数据知识；主要风险是隐私合规、数据污染争议、标记样本泄露以及与成员推断攻击之间的边界问题。

## 5. LLM 模型指纹与身份标识

大语言模型带来了新的挑战：输出是开放文本，调用方可通过提示改写、采样参数、后处理、SFT、LoRA、量化和模型合并改变行为；同时，许多实际验证只能访问 API。

### 5.1 触发式/指令式指纹

**Instructional Fingerprinting of LLMs** 通过轻量指令微调嵌入私有 key-response 对。验证时，模型发布方查询特定指令并检查目标输出是否被激活。其特点是实现简单、黑盒可验证、对部分下游微调有鲁棒性；局限是固定触发键可能被猜测、过滤或通过对抗性微调移除。

### 5.2 抗模型合并与抗擦除

模型合并使“谁贡献了能力”更难判断。**MergePrint** 针对模型合并攻击，在优化阶段模拟合并行为，使指纹在合并后仍可通过黑盒查询检测。2025 年左右的 **ImF（Implicit Fingerprint）** 等方法进一步关注语义自然性和抗擦除能力，尝试把所有权信息嵌入更自然的问答或推理行为中，以降低被过滤和定向移除的风险。

### 5.3 语义域统计信号

固定触发器的脆弱性促使研究转向“分布式、统计化”的指纹。**LLM Fingerprinting via Semantically Conditioned Watermarks** 将水印信号限制在某个语义域（例如特定语言或主题）中，而不是依赖少量固定问题。验证方可在该语义域内采样大量提示，对输出拼接后做统计检测。这类方法的优点是隐蔽、可扩展、对微调和量化更鲁棒；代价是需要更多查询、严谨阈值设置和对语义域分布的控制。

### 5.4 生命周期视角

2026 年的 LLM 身份技术综述开始用“隐式身份（implicit identity）”统一数据集、模型和生成内容三个层面的指纹/水印，并建议围绕三类目标评估：

- **可识别性**：能否区分目标模型、派生模型和无关模型；
- **鲁棒性**：能否抵抗微调、压缩、蒸馏、合并、提示改写和输出编辑；
- **可部署性**：是否影响模型质量、是否需要白盒权限、查询成本是否可接受、证据是否可解释。

## 6. AIGC 内容水印与模型指纹的关系

AIGC 内容水印主要用于判断“这段内容是否由某类模型生成”，不一定证明“某个可疑模型是否盗用了某个模型”。但它与模型指纹有两点交叉：

1. 输出水印可被蒸馏或微调进派生模型，从而成为模型身份的一部分；
2. 统计检测、假设检验、鲁棒性分析和攻击模型与模型指纹高度相似。

LLM 文本水印中，Kirchenbauer 等提出的绿名单/红名单 logit bias 框架是代表性方法：生成时提高绿名单 token 概率，检测时统计绿名单比例并给出 z-score 或 p-value。后续研究关注长文本可靠性、改写攻击、短文本检测、公开检测器安全性以及水印强度与文本质量之间的权衡。2024 年多篇 SoK 综述进一步把 AIGC 水印放在治理、溯源和法规合规背景下讨论。

## 7. 评测指标与工程检查表

设计或评估模型指纹方案时，建议至少覆盖以下维度：

| 维度 | 建议问题 |
| --- | --- |
| 准确性 | 在目标攻击下 TPR/FPR/AUC 如何？是否报告固定 FPR 下的召回？ |
| 唯一性 | 能否区分同数据不同初始化、同基础模型不同微调、相似架构独立模型？ |
| 鲁棒性 | 是否测试微调、剪枝、量化、蒸馏、抽取、迁移、模型合并、输出过滤？ |
| 隐蔽性 | 指纹查询或输出是否容易被发现、屏蔽或反向工程？ |
| 保真度 | 是否影响原模型准确率、对齐质量、生成质量或安全策略？ |
| 查询成本 | 黑盒验证需要多少查询？是否支持低置信度逐步加样？ |
| 统计严谨性 | 是否给出显著性水平、置信区间、多重检验校正和负样本设置？ |
| 法务可用性 | 证据链是否可复现、可解释、可审计，是否保存时间戳和版本信息？ |
| 隐私与合规 | 是否泄露私有训练样本、用户数据或触发器秘密？ |

工程落地时可以采用组合策略：

1. 对可控模型，在训练或发布阶段嵌入轻量水印/指纹；
2. 对不可改动的已训练模型，保留决策边界、自然样本和私有样本的多组行为指纹；
3. 对 LLM，同时维护固定触发集、语义域统计查询集和内容水印检测器；
4. 对关键证据保存模型版本、数据版本、查询脚本、随机种子、阈值和原始响应；
5. 定期用最新攻击重新评估阈值，避免一次性实验结论长期失效。

## 9. 开放问题

1. **法律证据标准不足**：学术指标通常关注 AUC 或 TPR/FPR，但真实纠纷需要可复现证据、审计日志、独立第三方验证和明确误报解释。
2. **强自适应攻击仍难覆盖**：攻击者可以过滤查询、重写输出、做反指纹训练、合并多个模型或对触发行为做异常检测。
3. **LLM 指纹与模型质量的权衡**：越强的指纹越可能影响对齐质量、安全策略或自然性；越隐蔽的指纹越难解释。
4. **基准难度不统一**：负样本、攻击流程、模型族和训练数据差异会显著影响结论，需要更标准化和更接近生产场景的 benchmark。
5. **数据权益与隐私冲突**：数据集指纹可帮助证明数据使用，但也可能引入隐私泄露、数据投毒或未经同意的标记问题。
6. **多方贡献模型的归属**：开源基座、SFT 数据、RLHF、工具调用、MoE、模型合并和蒸馏使“单一所有者”假设越来越不适用。

## 10. 后续研究建议

- 建立一个统一实验框架，复现 IPGuard、ModelDiff、DeepJudge、ModelGiF、QuRD 等分类器指纹方案，并在同一模型复用基准上比较。
- 为 LLM 构建黑盒验证脚本，覆盖固定触发集、语义域统计水印和内容水印检测三类证据。
- 设计“攻击回归测试集”：每次模型发布或微调后自动测试指纹在 SFT、LoRA、量化、剪枝、蒸馏和合并后的保留情况。
- 将模型指纹结果与供应链元数据结合，例如模型卡、数据卡、训练日志、签名哈希、许可证和发布渠道记录。
- 关注可解释证据输出：不仅给出“是否盗用”，还说明哪些查询、哪些统计量、哪些行为差异支撑该判断。
